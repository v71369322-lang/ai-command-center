# Главное меню владельца в Telegram

Облачная доработка поверх PR #33. На VPS автоматически не устанавливается;
действующий F32-бот остаётся на прежней версии до отдельного обновления.
Новые команды и кнопки можно проверять на телефоне только после доставки
этой версии и проверки подключения. Сейчас от владельца команд не требуется.

## Как пользоваться после обновления

`/start`, `/help` или `/menu` показывают небольшую клавиатуру:

| Кнопка | Существующая команда | Результат |
| --- | --- | --- |
| 📁 Проекты | `/projects` | Проекты и количество сохранённых запросов |
| 📥 Запросы | `/requests` | Последние сохранённые запросы |
| 🧪 Результаты тестов | `/tasks` | Состояние синтетических тестов этого подключения |
| ℹ️ Помощь | `/help` | Подсказки и повторное отображение меню |

Все кнопки — просмотр. Меню не запускает coding-agent, не снимает остановку,
не выдаёт grants и не подключает репозитории/CRM/платные API. Обычный текст
по-прежнему сохраняется в `NEEDS_PLANNING`, не объявляется выполненной задачей.
Для ввода текста можно использовать клавиатуру телефона. Аудиосообщения,
распознавание голоса и настоящее AI-планирование этим изменением не включены.

Клавиатура запрашивает `resize_keyboard` и `is_persistent`; окончательное
отображение/сворачивание зависит от клиента Telegram. Это не browser UI и не
подтверждённая physical iPhone/Safari приёмка. Прежние slash-команды сохранены.

## Контракт и границы

Поля `ReplyKeyboardMarkup` проверены 28.10.2026 по
[официальному Bot API](https://core.telegram.org/bots/api#replykeyboardmarkup).
Используются только две строки по две обычные текстовые `KeyboardButton`.
Transport разрешает только точную фиксированную структуру меню по canonical
JSON, включая настоящие bool; `1` вместо `true` не принимается.
Прежний validator одной inline-кнопки подтверждения остаётся действующим.

Произвольные клавиатуры, contact/location/poll requests, URL, Web Apps и новые
Bot API методы не допускаются. Подписи кнопок сопоставляются с командами только
после прежних owner/private-chat и secret checks. Только точное совпадение:
текст с дополнительными инструкциями остаётся данными, а не командой.
Новых таблиц, миграций, dependencies, host rights или credentials нет.

Меню использует существующие F1 admission/audit lock, durable inbox/delivery,
connection/revision/leadership guards. Повтор Update не создаёт второй receipt.
Обнаруженная гонка двух одновременных help/menu исправлена проверкой уже
завершённого inbox под той же транзакцией; проверки `finish` не ослаблены.
Crash до commit откатывает ответ; `resume_pending` восстанавливает один receipt.
Потеря HTTP-ответа оставляет send `UNCERTAIN`, автоматической пересылки нет.
Просмотр остаётся доступен при halt и не возобновляет новые исполнения.
