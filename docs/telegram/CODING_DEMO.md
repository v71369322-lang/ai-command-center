# Тестовый разработчик из Telegram

Продолжение Draft PR #30, `feat/telegram-project-queue`,
`4b2acb0462f217b599790989f1b9785b15d4cbfe`. Ветка сохраняет зависимости
F1/F2 и исправленного deployment PR #17. Ничего не объединяется и не
доставляется на VPS автоматически. Новые команды ещё не доступны в работающем
боте до отдельного проверенного обновления сервера.

## Команды после будущего обновления

- `/coding_plan` — прочитать план и ограничения, без запуска.
- `/coding_demo` — разрешить одно фиксированное mock-упражнение F2.
- `/tasks` — краткие состояния тестов текущего Telegram-подключения.
- `/status UUID` — этап и подтверждённый итог конкретного теста.
- `/cancel UUID` и `/stop` — существующая отмена и остановка допуска F1.

Упражнение исправляет сумму положительных чисел в локальном синтетическом
репозитории `f2-synthetic-sum`. Разрешён только `calculator.py`, исходная
Git-ревизия и acceptance tests фиксированы F2. Provider строго `mock`,
max_iterations=2, max_units=2, max_tokens=2048, max_seconds=15.
Единицы и токены синтетические, это не RUB/USD и не разрешение оплаты.
Аргументы с другой моделью, репозиторием, бюджетом или задачей не принимаются.

Команда разрешает этап один раз, по той же F1-политике, что кнопка существующей
панели F2. Отдельные подтверждения на каждый файл/тест не вводятся. Платный
provider по-прежнему требует отдельного ограниченного разрешения gateway;
команда Telegram его не создаёт и не подтверждает.

## Реальный кодовый путь

Telegram → существующий Store/Outbox → Redis → worker → runtime broker →
networkless coding container → провал acceptance tests → исправление →
отдельный verifier container → mock PR в состоянии задачи → уведомление Telegram.

Git-коммиты, изменение Python-функции, тесты и независимое воспроизведение
действительно выполняются существующим F2. Детерминированный mock заранее
возвращает ошибочную, затем исправленную реализацию: это не AI-рассуждение.
PR только подготовлен в mock-режиме: `published=false`, `url=null`.
Новых оркестратора, provider, launcher, таблиц или миграций нет.

Обычный сохранённый текст не превращается в coding-задачу. CRM, внешние
репозитории и произвольные пользовательские задания не подключаются.
Выполнение настоящей бизнес-задачи не заявляется.

## Атомарность и полномочия

Store.create получил внутренний optional transaction callback по образцу
существующих approve/cancel. HTTP-контракт его не предоставляет. F1 Task,
Outbox, Telegram task binding, audit и ответ фиксируются одной транзакцией;
ошибка/отзыв до commit откатывает их вместе. Аргументы прежних Python/HTTP
вызовов сохраняются. Доступ к Docker/credentials Telegram не получает.

Исходный Update привязан к владельцу/private chat, текущему source revision,
epoch F1 и серверному сроку 120 секунд. Повтор или restart не продлевает срок.
Halt/recovery до приёма не сохраняет команду на будущее. Смена epoch, срока
или исходной ревизии до фиксации запрещает создание Task. Вся дальнейшая
работа использует прежние lease/fencing/cancellation/watchdog F1/F2.

Повтор Update не создаёт второй Task/Outbox. Завершённая или отменённая задача
не перезапускается повтором. Ошибка отправки ответа не отменяет уже
зафиксированную задачу: действует прежняя durable доставка, UNCERTAIN не
повторяется вслепую. Подтверждённая отмена не обещается до проверки runtime.

Чтение и уведомления требуют исходного request key, текущего профиля, точного
mock payload/hash и audit binding. Чужие/web-задачи и подменённый provider
исключаются. Успех требует F1 verifier record и hash артефакта; история
исправления/статус mock PR дополнительно связаны с coding_complete evidence hash
и fence. Тексты provider, summary, исходники, PR URL и произвольные причины
ошибок не копируются в сообщение. Для списка пяти тестов используются короткие
подтверждённые итоги, чтобы сохранить прежние лимиты transport.

## Проверки и ограничения доказательств

Новые tests используют настоящий PostgreSQL/Redis и mock Bot API: точный scope,
частные сообщения, отказ аргументов, atomic rollback/recovery, concurrent replay,
halt/recovery, expiry/epoch/source revision, отмена и подмена результатов.
Отдельный интеграционный тест проходит настоящий broker и два sandbox-контейнера.
Расширенный service smoke проверяет Telegram container без Docker socket →
реальные PG/Redis/worker/broker → coding repair/replay → Telegram report.

Эти проверки облачные; они не подтверждают rootless/systemd/iPhone acceptance
на VPS, настоящего AI или реальную публикацию GitHub PR. Точные результаты,
final SHA и CI публикуются в Draft PR этой ветки, без сложения пересекающихся
наборов. Серверный канал F33 и его фактическая установка этой работой не меняются.
