# Управление очередью запросов Telegram

Обычный текст в приватном owner-чате остаётся сохранённым запросом со статусом
`NEEDS_PLANNING`. Команды с неизвестным `/name` больше не превращаются в такие
запросы: бот отвечает фиксированной подсказкой и завершает только входящую
команду. Это предотвращает появление ложных задач из-за опечатки или команды,
которой ещё нет в установленной версии.

Для незапланированного запроса доступны две обратимые owner-команды:

```text
/archive_request 131179132
/restore_request 131179132
```

Архивирование меняет состояние строки на `ARCHIVED` и исключает её из `/requests`,
`/projects`, `/attention`, `/queue` и последующего планирования. Текст, назначение
проекта и исходный Telegram intake не удаляются. В append-only audit сохраняются
fingerprint, номер версии, целевое состояние и отдельная операция команды.
Повтор исходного Telegram update не создаёт запрос заново.

Восстановление возвращает ту же запись в `NEEDS_PLANNING`; новая копия и новая
бизнес-задача не создаются. Переход запрещён, если для запроса уже существует
planning task или сохранённый план. Тогда жизненный цикл должен разбираться по
существующей задаче и финансовому журналу, а не скрываться архивированием.

Обе команды работают только внутри текущего Telegram profile, не обращаются к
AI, GitHub или CRM, не создают grants и не разрешают выполнение. История переходов
проверяется перед каждым изменением; повреждённая или несогласованная история
останавливает операцию.
