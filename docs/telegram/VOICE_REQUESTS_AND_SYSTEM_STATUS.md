# Голосовые поручения и статус компонентов

Telegram принимает два разных типа голосовых заметок владельца:

- обычное голосовое или подпись `/task` — поручение для будущей очереди проектов;
- подпись `/calendar` — заметка для календаря.

На этапе приёма сохраняются только ограниченные метаданные файла. Бот не скачивает
аудио, не вызывает AI, не создаёт задачу и не выбирает проект. Будущий доверенный
расшифровщик обязан вернуть текст с хешем конкретного аудио. Даже успешно проверенная
расшифровка показывается владельцу отдельной карточкой. Только наблюдённое нажатие
`Сохранить запрос` превращает callback в неизменяемую запись очереди и предлагает
выбрать проект. `Удалить расшифровку` завершает маршрут без создания запроса.
Подтверждение текста не становится разрешением на выполнение.

Команда `/voice` показывает число голосовых поручений, ожидающих расшифровки.
Команда `/system` объясняет роли контура: Telegram-диспетчер, AI-аналитик,
изолированный исполнитель, проверяющий и watchdog. Это локальная сводка: она не
проверяет VPS или внешних провайдеров и не объявляет обычные проекты подключёнными.

Для подключения первого проекта после доставки этой версии нужны отдельные этапы:

1. ограничить GitHub App одним репозиторием;
2. выполнить read-only инвентаризацию и закрепить исходную ревизию;
3. проверить анализ и исправление на синтетической ветке;
4. разрешить создание отдельной ветки и Draft PR;
5. оставить merge и production deployment за отдельным решением владельца.
