# Очередь запросов по проектам

Отдельная доработка поверх PR #26, source 316dc16. Подготовленный вечерний
F32-пакет остаётся на 316dc16; эта ветка не включается в него автоматически.

Панель «Проекты и запросы» позволяет владельцу выбрать AI Commander,
«Ваниль и Сахар», LNAuto или Capital Lab для сохранённого Telegram-запроса,
снять назначение и отфильтровать очередь. Все запросы остаются NEEDS_PLANNING.
Выбор проекта не выдаёт прав, не создаёт Task/Approval/Outbox, не запускает AI,
не подключает репозиторий или CRM. Реальные проектные интеграции отключены.

GET /api/project-inbox и POST /api/project-inbox/assign требуют owner identity.
Для password/OIDC сессий сохраняются CSRF/origin/revocation проверки. Контракт
запрещает лишние поля и неизвестные project IDs; ошибки не отражают входные данные.

Исходный capture intent/fingerprint не меняется. Назначение — append-only audit
event project_request_classified, связанный с request ID/fingerprint, версией и
operation UUID. F1 admission/audit lock сериализует операции. Устаревшая версия
отклоняется; повтор operation возвращает прежний receipt, а повтор с другим
содержимым отклоняется. После потери ответа можно сверить GET или повторить ту
же операцию; UI требует обновить список перед новой попыткой. История сохраняется
в PostgreSQL и existing backup/audit механизмах, без новой таблицы/миграции.

Оригинал запроса проверяется по capture fingerprint и owner received audit
anchor, типу/размеру текста и известным секретам. Это не универсальный DLP.
Номер/проект — метаданные, не execution authority. Будущий coding workflow
обязан отдельно проверять разрешённый репозиторий/ревизию/бюджет.

Ограничения: до 1000 pending requests и 1000 assignment events; выдача до 50
последних запросов после server-side фильтра. Счётчики охватывают всю очередь.
Панель обновляется вручную/после сохранения. История ограничена намеренно;
автоматическое удаление или бесконечное хранение не реализованы.

При изменении проекта обновляется также checkpoint основной панели; назначение
никогда само не снимает halted admission. Подтверждение сохранения отображается
после обновления состояния. При logout данные скрываются, запросы прерываются;
неопределённый HTTP результат не превращается в автоматический повтор записи.

Проверки: tests/test_project_inbox.py — actual PostgreSQL, роли, CSRF, повторы,
конкуренция, crash/response loss, целостность, лимиты и неизменность полномочий.
tests/test_project_inbox_mobile.py — Chromium 320/390, реальные API/PG, assign /
filter / clear, XSS, ошибки, logout/operator и явный resume со свежим checkpoint.
Это не проверка настоящего Safari/Telegram, VPS или подключения внешних проектов.
Итоговые результаты и SHA фиксируются в отдельном Draft PR.
