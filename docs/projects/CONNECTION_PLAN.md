# План подключения проектов

Облачная доработка поверх PR #61. Владелец попросил продолжить подготовку без
компьютера после объяснения трёх связей: репозиторий, изолированная проверка,
канал доставки на сервер. Это отображение будущего подключения в Commander;
реальные проекты, GitHub Apps и VPS здесь не подключаются.

В панели «Проекты и запросы» у каждого существующего project ID появился
раскрываемый план. Он показывает ожидаемое имя репозитория и три пункта со
статусом «не проверено». Историческое наличие репозитория в GitHub не является
проверкой доступа runtime Commander. План не показывает здоровье сервера,
процент готовности, действующую версию или пригодность к запуску.

GET /api/projects/{project_id}/connection-plan использует прежнюю owner identity.
Разрешены только четыре существующих ID; неизвестные IDs и write-методы не
создают подключение. Ответ всегда PLAN_ONLY, checked_at=null,
external_checks_performed=false, execution_connected=false, actions_enabled=[].
Он не читает provider credentials, не делает сетевых проверок и не изменяет
задачи, grants, deployment profile, очередь или финансовые резервы. Новых
таблиц/миграций/настроек окружения нет. OpenAPI получает один GET endpoint;
контракт существующей очереди сохранён.

План загружается только при раскрытии. Ошибка/некорректный ответ скрывает только
этот план: назначение запросов и управление остаются доступны. UI отвергает
ложные признаки verified/live/connected, чужой project ID и небезопасное имя
репозитория; не отражает тексты серверных ошибок. Закрытие/logout/unmount
прерывают запрос; повтор загрузки является только GET плана.

Следующие отдельные этапы: после реального recovery-теста выбрать один проект,
проверить scoped repository binding, воспроизводимые тесты на синтетических
данных, затем защищённую доставку и postcheck на его VPS. Способ хранения и
проверки живых подключений ещё не реализован этим endpoint. Он не выдаёт
полномочий будущему исполнителю и не меняет одноразовые F1 approvals.

Runtime recovery bf91c05, его build-only пакет и все существующие release pairs
сохранены. Эта UI/API доработка сама на VPS не устанавливается. Browser tests
используют Chromium/настоящий локальный API и PostgreSQL; это не iPhone/VPS
или проверка реального проектного подключения.

Проверки охватывают owner/anonymous/operator/agent, неизвестные IDs и запрещённые
write-запросы, отсутствие изменения полномочий при halt, независимость объектов
плана, Chromium320/390, lazy GET, ложные live/verified/connected/actions/checked_at
и external-checks признаки, небезопасный repository text, доступность assignment
при ошибке плана, retry и выход во время незавершённой загрузки. Итоговые counts,
HEAD и CI evidence сохраняются в отдельном Draft PR.
