# F33 bootstrap: исправление ограниченного PATH

28 октября 2026 владелец выполнил начальный блок установки. Проверка старого
enroll.py SHA-256 прошла, затем первая, plan-only команда вернула
`operations_enrollment_unconfirmed`. JSON плана не был выведен: из-за set -e
вторая команда с --install не запускалась. Установка не считается выполненной.

Локально воспроизведён дефект: Ubuntu размещает runuser в /usr/sbin, а bootstrap
вызывал его по короткому имени при PATH=/usr/bin:/bin. Исправлены оба root-вызова
на /usr/sbin/runuser. Лимиты недоверенного Git применяются после смены UID через
фиксированный /usr/bin/prlimit, поскольку runuser может сбрасывать лимиты.
Ограниченный PATH и запрет Git transports сохранены.

Регрессии: root-ветка с ограниченным PATH; настоящий root plan в networkless
Ubuntu 24.04 с Git от отдельного UID; реальная генерация тестового Ed25519-ключа
через runuser. Это тестовые ключи в disposable tmpfs, не credentials VPS.

## Восстановление без повторной доставки исходников

На VPS остаётся checkout ops/bounded-vps-enrollment. Установленный пакет
оператора по-прежнему берётся из явно разрешённого source commit
`eec068fa4a3558033e36cb572d3f9b6c081758fc`: app modules/units/protocol не менялись.
Исправление относится только к одноразовому установщику; он не входит в
копируемый runtime package. Эта зависимость не подменяется скрытой копией кода.

Допустим защищённый private snapshot прежнего bootstrap, с проверкой исходного
SHA-256 `527499daa7995c317783089b6e93e11103a7b33b81595085300e68e042e5d488`,
ровно тремя проверенными текстовыми заменами и обязательной проверкой нового
SHA-256 `5aa92cb60a3ac4a79a0d9a8e9c22b85e0c86652221b9b0ba1bc0a3e974a5bd3e`.
Результат побайтно совпадает с исправленным enroll.py этого PR.
Исходный checkout, receipts, Docker images и private application state
не редактируются. При несовпадении или существующих enrollment targets — отказ,
не перезапись. Публичный код/metadata устанавливаются при scoped umask 022;
явные режимы private key/directories остаются 0600/0700.

Каталог и пределы выданного разрешения не изменены: canonical SHA-256
`2309a2f9fc90609253228d7cf8d052f0f5c81a0a685a6a349656dd7c177f3a6a`,
runtime один час, до 32 операций, max_updates=0. Начальное окно установки,
записанное на ops-ветке, само исправление не продлевает.
Реальный root install и последующая регистрация остаются неподтверждёнными
до получения результатов владельца. Нового root-доступа у облачного агента нет.
