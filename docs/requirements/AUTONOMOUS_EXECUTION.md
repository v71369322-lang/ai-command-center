# AUTONOMOUS EXECUTION WITHOUT PER-COMMAND HUMAN APPROVAL

ID: **R-F1-AUTO-01**. Статус: **APPROVED**, источник: прямое задание владельца
«AI COMMAND CENTER — НЕЗАВИСИМОЕ РЕВЬЮ F1 И АВТОНОМНОСТЬ ИСПОЛНИТЕЛЕЙ»,
раздел 5 и заключительный принцип безопасной работы в изолированной среде.
Это новый источник, не восстановленный исторический H-пункт. R01–R51/D01–D30
и их исторические статусы не меняются. Приоритет: P0 (DERIVED).

## Обязательное поведение

Одно разрешение на ограниченный этап позволяет длительное неинтерактивное
выполнение всей обычной разработки в его пределах: чтение, isolated branch,
изменения, commits, тесты, security checks, сборки, bounded repair/retry,
документация, PR и доказательный отчёт. Владелец не подтверждает shell-команды
по одной. Оркестратор выдаёт минимальные полномочия; независимый verifier
проверяет результаты; все действия сохраняются в журнале.

Человек привлекается при выходе за разрешённый scope, существенном риске,
исчерпании разрешённых лимитов или необходимости отдельного решения. Бюджетный
потолок не разрешает покупки. Новые расходы, расширение доступа, опасная
инфраструктура, protected merge, реальные данные/API и следующий этап остаются
отдельными gates. Молчание не является согласием.

Используются только официальные неинтерактивные интерфейсы. Нельзя автоматически
нажимать кнопки согласования или обходить защиту провайдера. Если интерфейс
не поддерживает требуемый режим, выбирается совместимый исполнитель только
в пределах разрешений/данных/бюджета либо задача безопасно завершается с
отчётом о блокировке. AI не повышает собственные лимиты и полномочия.

## Модель реализации — DERIVED, не дополнительное разрешение

Версионированный stage grant связывает task/scope, Git base, разрешённые
операции и ресурсы, бюджеты/time/attempt/concurrency, expiry и revocation.
Детерминированная policy проверяет грант перед действиями. Обычные операции
внутри scope не превращаются в отдельные approval cards; чувствительные
действия требуют точного отдельного consent. Revocation/stop блокируют новые
действия, сверяют незавершённые и сохраняют evidence.

## Критерии проверки — DERIVED, ещё не выполнены для реального AI

1. Одна stage approval → branch/edit/test/build/bounded repair/report без
   per-command user prompts в поддерживаемом интерфейсе.
2. Попытки выйти за scope, получить чужие secrets, увеличить лимит, потратить
   деньги или merge без grant блокируются и журналируются.
3. Expiry/revoke/stop прекращают новые действия; неопределённый исход сверяется
   перед повтором. Несовместимый provider не объявляется автономным.
4. Отчёт связывает exact revisions, тесты, артефакты, grants и остаточные gates.
