## Состояние подготовки

Ветка `feat/jarvis-assistant-only-stage1` поверх проверенной цепочки live956c19f
и документации2c751f4/4f4436b. Origin проверен/fetch выполнен; main остаётся
f5ff8b2757b1b759b08a173fdac9d3e51f84d227, не является базой этой зависимой цепочки.
Этот документ фиксирует подготовку; установленный assistant-only runtime пока
не заявляется. Старые failed transient units не переисполнять.

Новый opt-in `assistant_only: true`:

- Оставляет db, redis, api, telegram и voice; worker/broker/watchdog отсутствуют.
- Технические HTTP/Telegram команды, новые F1 jobs, approval/claim/retry и gateway
  authority отвергаются. Старые pending developer intents тоже получают отказ.
- Не монтирует execution socket, broker ledger или provider/publisher credentials
  приложениям. Сохраняет owner authorization и существующую durable Telegram очередь.
- Сохраняет Telegram owner/bot/token binding, voice cutoff/model/profile, schema,
  data root и PostgreSQL/Redis image pins. Меняются только code/image revision и
  необходимый профиль голоса. Не создаёт нового механизма полномочий.
- Штатный deployment продолжает backup/boot/lock/exact approval/postcheck. При
  переходе останавливает старые сервисы через предыдущий bundle, чтобы оставшиеся
  вне нового compose developer containers не продолжили работать как orphan.
- Assistant postcheck проверяет реальные image/env/mount/network/resource metadata,
  отсутствие трёх developer containers, финансовый ledger, halt и fresh voice health.
- Новый adapter `infra/vps/activate_assistant_candidate.py` использует прежний
  activation/deployment transaction и штатный reconcile; не подменяет журналы.
- Контрольные запросы standalone assistant больше не требуют execution daemon.
  Первый cutover всё ещё требует пустой execution runtime и проверенный ledger.

Образы legacy executor не собираются для assistant-only prepare. Старые исходники,
таблицы, grants и артефакты пока сохранены для истории/отката. Это ограничение
runtime, а не заявление о полном удалении всех старых Python модулей.

## Исправления, необходимые для безопасного перехода

1. Operator maintenance повторяет только вход в transaction при точно распознанной
   конкуренции за Control row1: до5 попыток/пауза1s; тело и commit не переигрываются.
   Не повышает SQL timeout/память/CPU и не меняет обычные app transactions.
2. Только в assistant mode точный idle/paused offline voice heartbeat того же
   Telegram profile допускается в checkpoint проекции owner `/resume`. Unknown,
   paid, processing, чужой profile и события с дополнительными полями остаются
   препятствием. TTL/epoch/source/owner/card checks сохранены.
3. Реальный restore drill выявил `No space left on device`: неограниченный
   `json_agg(... ORDER BY ...)` журнала создавал sort temp на128MiB tmpfs. Новый
   keyset reader по256 строк проверяет всю цепочку и anchor без увеличения лимитов.
