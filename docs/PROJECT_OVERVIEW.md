# AI Command Center: назначение и границы

Статус: исходный проектный контекст этапа 0A. Основание — задание владельца на этап 0A; полный исторический контекст ещё не передан.

AI Command Center — персональная облачная система управления AI-агентами, разработкой, проектами, мониторингом и бизнес-аналитикой. Владелец управляет системой с телефона через Telegram и адаптивную mobile-first веб-панель. Оба интерфейса используют общее состояние задач и согласований.

Постоянный управляющий контур в будущем размещается на отдельном VPS. Ресурсоёмкие AI-агенты запускаются по запросу в изолированных облачных средах. Центр управляет внешними проектами через контролируемые подключения и не является единым сервером для всех проектов.

## Будущий первый MVP

В границы будущего MVP входят Telegram, mobile-first веб-панель, оркестратор, PostgreSQL, очередь задач, один изолированный тестовый AI-агент, журнал выполнения, согласования, ограничения расходов и базовый мониторинг. Это описание целевого объёма, а не разрешение на реализацию.

## Текущий этап 0A

Разрешены проверка репозитория, отдельная рабочая ветка, первоначальная структура документации, правила AI-агентов, фиксация утверждённых принципов и открытых предположений, проверка изменений и создание pull request без merge.

Запрещены покупка и настройка VPS, создание производственных сервисов, подключение реальных API и клиентских данных, полноценная реализация backend/frontend, новые архитектурные решения вместо владельца и изменения существующих проектов без отдельного разрешения.

## Документация и последующие задания

- `ARCHITECTURE_BASELINE.md` — утверждённые владельцем исходные принципы.
- `OPEN_ASSUMPTIONS.md` — технические вопросы без статуса решения.
- `architecture/` — будущие описания архитектуры и границ модулей.
- `requirements/` — будущие требования и критерии приёмки.
- `decisions/` — место для реестра архитектурных решений, который будет передан отдельным заданием.
- `roadmap/` — будущие этапы и зависимости работ.
- `security/` — будущая детализация безопасности, доступа и восстановления.

Полный реестр архитектурных решений и итоговый аудит будут переданы отдельными заданиями. Содержание этапа 0B должно быть получено от владельца; текущая документация его не утверждает и не разрешает начинать реализацию.
